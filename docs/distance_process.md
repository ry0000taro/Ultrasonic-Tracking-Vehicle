# 距離データ処理 Distance_Process（実装メモ）

2026-11-13 時点の**実装**(`Core/Src/distance_process.c` / `Core/Inc/distance_process.h`)の内容。
Notion「超音波計測 機能モジュール表」の `Distance_Process` と食い違う点は、**実装を正**とする（下の「Notion との差異」）。

- 層: 制御層（Model）。ドライバ層の `ultrasonic.c` には触らない。
- 呼び出し: `Ultrasonic_GetResult(dist, no_resp)` のあとに `Distance_Process(dist, &out)`。
  現状は `main.c` の超音波デモループ（60msごと）だけ。状態・判定層、位置制御、向き制御からはまだ使っていない。

## 関数仕様

```c
int Distance_Process(const float dist_mm[4], UsResult *out);
```

| 返り値 | 意味 |
|---|---|
| 0 | 位置推定に成功（`estimated=1`） |
| -1 | 位置を推定できない（有効値が1個以下／収束しない／縮退） |
| -2 | `dist_mm` または `out` が NULL |

`UsResult`

| メンバ | 内容 |
|---|---|
| `dist_mm[4]` | センサ0〜3の距離[mm]。範囲外（応答なしの 0 を含む）は −1 |
| `detect` | 有効値のどれかが 300mm 以内なら 1 |
| `x_mm`, `y_mm` | 対象の位置[mm]。`estimated=0` のときは 0 |
| `estimated` | 位置の推定に成功したか |

### 処理の流れ
1. 20〜4000mm の値を有効とする（NaN も無効）。無効は `out->dist_mm[i] = -1`。
2. 有効値のどれかが 300mm 以内なら `detect=1`（有効値の個数に関係なく判定する）。
3. 有効値が 2個以上なら、ガウス・ニュートン法で (X, Y) を推定する。1個以下なら推定せず −1 を返す。
4. 成功したら前回値を更新して 0 を返す。

### 位置推定
- モデル: `dᵢ = √((X−xᵢ)² + (Y−yᵢ)²)`、残差の二乗和を最小化。パラメータ2個なので 2×2 の正規方程式を直接解く（動的確保なし、`float`）。
- 初期値: 前回の推定値。初回は (0, `DP_INIT_FOLLOW_MM`)。
- 反復: 最大 `DP_GN_MAX_ITER`(20)回。X・Y 両方のステップが `DP_GN_EPS_MM`(1mm) 未満で収束。
- 失敗条件: 行列式 < 1e-6（縮退）／非有限値／収束しない。
- Y>0 の側に置く: 更新後に Y<1mm なら、Y<0 なら符号を反転、いずれも最低 1mm に押し戻す。
- 推定点がセンサ位置に 1mm 未満まで重なったときは、微分できないので Y 方向にずらして続ける。

### 前回値の扱い
| 状況 | 前回値 |
|---|---|
| 推定成功 | 更新する |
| 有効値が1個以下 | そのまま残す |
| 収束せず／縮退で失敗 | 初回値 (0, 500) に戻す（発散した初期値を引きずらないため） |

## 定数（`distance_process.h`）
| 定数 | 値 | 備考 |
|---|---|---|
| `DP_RANGE_MIN_MM` / `DP_RANGE_MAX_MM` | 20 / 4000 | 有効範囲 |
| `DP_DETECT_MM` | 300 | 対象検出距離 |
| `DP_INIT_FOLLOW_MM` | 500 | **仮の値**。初回初期値の追従距離。要件書の追従距離は 100mm（US-03）だが、Notion の本ページに値の指定がなく、仮に 500 とした |
| `DP_SENSOR_X_MM` / `DP_SENSOR_Y_MM` | {−88,−38,38,88} / {37,20,20,37} | 図面の取付ボルト穴から読んだ**仮の値**（US-06）。発音面中心へ直すときはこの2つだけ直す |

座標系は Notion に従う（原点＝底板前端と中心線の交点、X右が正、Y前方が正）。

## Notion との差異（実装を正とする）
| 項目 | Notion | 実装 |
|---|---|---|
| NULL 引数 | 記載なし | −2 を返す |
| 推定失敗時の `x_mm`, `y_mm` | 「他の値は更新する」のみ | 0 にする |
| 失敗後の前回値 | 「初期値は前回の推定値」のみ | 収束せず失敗したら初回値に戻す |
| 初回の追従距離 | (0, 追従距離) | 500mm の仮の値（上記） |
| 解の選択 | 必ず Y>0 の側に置く | Y を 1mm 以上に押し戻す方式で実現 |
| 残差の検査 | 記載なし | **なし**（下記の既知の制限） |

## 既知の制限
実機ログと PC 上のシミュレーション（実装の Python 写し。実機ではない）で確認した。

1. **整合しない入力は発散して失敗する**。例: センサ0=1628mm、センサ1=168mm（取付間隔は約53mmなので、2つの円が交わらない）。X が万単位に発散し、行列式が下限を割って `estimated=0`。センサの向きが違う（22.5°と7.5°）ので別の物を見ているのが実際の原因。
2. **有効2個だけ（隣り合うセンサ）は X の精度が出ない**。整合した値なら復元するが、±3mm の誤差で X が約54mmずれる。
3. **有効3個では誤差は小さい**（±3mm で X・Y とも数 mm）。ただし外れ値が1個混じると、多くは失敗（安全側）だが、発散せずに収束してしまうことがある。例: 真値 (100,600) でセンサ1だけ 168 → (−123, 460) で `estimated=1`、RMS残差約200mm。**残差を検査していないため成功として返す**。
4. **有効1個**では位置を推定しない（`detect` のみ判定）。正面距離は Notion の方針どおり作っていない。
5. 60ms ごとに片方の組だけ更新されるので、対象が動くと最大 60ms 分の誤差が出る（Notion に記載あり）。
